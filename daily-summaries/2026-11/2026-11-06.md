# Daily Summary - 2026-11-05

## Key highlights
- NVIDIA driver 620.70.06 / CUDA 13.5 now runs an IOMMU/PCI ACS topology check before allowing PCIe P2P via cuDeviceCanAccessPeer and cuCtxEnablePeerAccess, refusing if Request or Completion Redirect is set without Upstream Forwarding; CUDA_DISABLE_IOMMU_ACS_P2P_CAPABILITY_CHECK=1 bypasses it. The 615-branch patch-libcuda-p2p.py signatures match 0 times on 620; can-access and peer setup merged, so the P2P patch is 3 sites/4 bytes, with kernel port changes for GR100/GR102 NVOC HAL masks. [(1)](https://discord.com/channels/1466898002793857221/1474436297878933699/1568059186439389236) [(2)](https://discord.com/channels/1466898002793857221/1474436297878933699/1568061070634131459)
- spark-local-inference commit c2606aae fixes disk-engram prefill on 4x RTX PRO 6000 + WD SN8100 (XFS, 1 worker, 32G row cache): cold 250k prefill rises 6,915 -> 11,385 tok/s, gather 42.7 -> 11.3s, SSD hit 26.3 -> 82.4%; 500k reaches 11,566 tok/s with 92.6% hit. Earlier alignment rework (merge base 78b18b1c) cut reads 33GB -> 4.3GB but only reached 7,094 tok/s; fio shows SN8100 needs 16 submitters/512 depth (2,312k vs 440k IOPS). On c2606aae, 4 workers lose to 1 (9,759 vs 10,919 tok/s); row-cache sweet spot 32G; PR #216 reopens Linux --embedding-table-workers.
