## Benchmarks and implementation findings
- SGLang HiCache config: when the RAM KV pool is smaller than the GPU KV pool, write-through locks the entire RAM pool because it exists in GPU and leaves no room for disk restores; write-back is recommended for that configuration. [(jump)](https://discord.com/channels/1466898002793857221/1528331644933767190/1550419591652708432)
- On a TP2 setup with a 6.3M-token VRAM KV cache and a 17.8M-token RAM HiCache, a 95.8% cache hit rate was reported over 2.7B tokens and 38k requests, running a Sep 7 r22 image. [(jump)](https://discord.com/channels/1466898002793857221/1528331644933767190/1550527752569098244)
- After three days of trying to get a stable and fast TP2 running, a user reported that a TP1 setup worked best. The final serving configuration was: jpezzulli/sglang-rtxpro6000 (SGLang fork, branch pennyroyal-v2.5.1), Qwen3.8-Flash-Next NVFP4 (RadixArk checkpoint), 524,288-token context (262,144 native x2 via YaRN factor-2), MTP/NEXTN + FR-Spec speculative decoding, PLE table offloaded to host RAM, HiCache/NIXL disabled. Measured results were median decode 208 tok/s, warm short-prompt 458 tok/s, long-decode 227 tok/s, and TTFT 262 ms. [(1)](https://discord.com/channels/1466898002793857221/1528331644933767190/1550584677666914316) [(2)](https://discord.com/channels/1466898002793857221/1528331644933767190/1550588773434400801) [(3)](https://discord.com/channels/1466898002793857221/1528331644933767190/1550589535497494711)
